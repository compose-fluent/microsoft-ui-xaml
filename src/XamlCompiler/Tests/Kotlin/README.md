# Kotlin declaration protocol

The existing executable accepts `Language: "Kotlin"`, `LanguageSourceExtension: ".kt"`, and `IsPass1: true` in its normal input JSON. Supply the same WinMD reference set as the application, reference **directories** in `ReferenceAssemblyPaths`, and a distinct output/saved-state directory. The output JSON's `KotlinDeclarations` property is a complete schema-version-3 snapshot. Error output must not be consumed as a declaration input.

The snapshot contains pages sorted by `x:Class`, relative resource paths, WinRT base and element names, harvester connection IDs, fields, event/delegate names and 1-based source locations. Classless resources have their own list. It deliberately does not guess Kotlin projection names. Kotlin resolves these using its metadata/generator mapping. Empty input produces an empty snapshot. Kotlin analysis always visits every input; the build caller owns incremental checks.

Protocol v3 supports known SDK element types, named elements, events, `x:Properties`, compiled bindings, template scopes, phased bindings and deferred elements. Final compilation uses `IsPass1: false`, `KotlinSymbols`, `LocalAssembly` containing the Kotlin-generated WinMD, and the selected framework's `GenXbfPath`. It reuses the existing connection-ID rewriter and GenXbf and returns `KotlinImplementation` with the declaration fingerprint and connection plan. It emits no C#/C++ placeholder source. XBF compilation does not by itself imply Kotlin runtime loading support.

Run `Test-DeclarationIndex.ps1` with `-Compiler`, `-ReferenceDirectories` and `-OutputDirectory`. It invokes the real executable and validates repeat/rename/deletion/resource handling, unsupported-feature failure and existing C#/CppWinRT Pass 1 source generation. Add `-Framework uwp` for the UWP build and `-GenXbfDirectory` to compile a nonempty resource dictionary to XBF using the real framework compiler. Output files are retained for inspection.

An optional `KotlinSymbols` input carries the schema-version-3 semantic sidecar from Kotlin compilation: the declaration snapshot and its fingerprint, plus each page's ordinary handler names, return types and parameter types. When present, declarations must match the current harvest and handler signatures must match the actual WinMD delegate `Invoke` method. Private methods are represented only in this compile-time sidecar. The smoke script also checks valid/invalid signatures and stale declarations.

The Kotlin consumer fixture was generated with Windows App SDK 2.5.1's WinUI 2.3.9, Foundation 2.3.12, InteractiveExperiences 2.1.9 (metadata/10.0.18362.0), and Windows SDK contracts 10.0.26100.1742. These are test provenance, not hard-coded protocol dependencies.

The same compiler sources build either framework: pass `/p:KotlinXamlFramework=winui` (the default) or `/p:KotlinXamlFramework=uwp` to MSBuild, using separate output directories. Set input JSON `XamlFramework` to the matching lower-case value; an omitted field uses the compiler artifact's framework, preserving the existing WinUI contract. Declaration snapshots include `Framework`, and semantic validation rejects a snapshot from the other framework. UWP resolves `Windows.UI.Xaml` from the selected Windows SDK contracts; WinUI resolves `Microsoft.UI.Xaml` from its Windows App SDK package. Individual SDK contract WinMD references must remain ordinary references rather than `IsSystemReference` facade references, so they are available during Pass 1.

For UWP, `GenXbfPath` is the selected SDK's `bin/<version>/XamlCompiler` directory (or `bin/<version>` for older layouts); the compiler appends the host architecture. For WinUI it is the package's `tools` directory. CI discovers installed SDK roots and runs both framework builds, declaration tests and actual XBF compilation. `Package-KotlinXamlCompiler.ps1 -Framework uwp -WindowsSdkVersions <tested-version>` creates an `-uwp-win-x64` archive with its SDK compatibility recorded in `kotlin-xamlc.json`; the WinUI archive name remains unchanged. The consumer chooses one compiler package and supplies the matching reference and GenXbf paths.
